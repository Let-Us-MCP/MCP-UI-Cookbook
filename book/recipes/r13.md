## What stays local, what crosses

| Normally local | Worth crossing |
|---|---|
| Fill in fields, validate | "What do these quiet hours mean for the digest?" |
| Save, discard | "Set this up like the platform team's" |
| Preview the accent colour | |

Almost nothing crosses. A settings form that consults a model is a settings
form with a latency problem.

## Native pickers, host formatting

`<input type="date">`, `type="time">` and `type="color">` do the collecting.
`Intl` with `hostContext.locale` and `hostContext.timeZone` does the
displaying. Press "Switch to ja-JP / Tokyo": the stored values do not change
and everything rendered does.

That separation is the whole of Chapter 12. The picker's value is an ISO
string; the user's understanding of it is a formatted one; the host is the
only source for which format is right.

## Validation that waits

<!-- listing: illustrative -->
```js
const email = /^[^@\s]+@[^@\s]+\.[^@\s]+$/.test(values.email);
if (!email && (!live || $("#email").dataset.touched)) { /* show the error */ }
```

A `touched` flag per field, set on blur. The error appears after the user has
left the field once, and updates live from then on. Telling somebody their
address is invalid while they are typing the at sign is the fastest way to
make a form feel hostile.

## Save and discard mean what they say

Both are disabled until something changes. Discard confirms, because it
destroys work. Save validates first, focuses the first invalid field if there
is one, and announces the failure so a screen reader user learns about it at
the same moment a sighted user does.

The server validates again and can reject. Press Save with a bad address after
editing it past the client check: the server's message is shown and the form
stays dirty. Client-side validation is a courtesy; the server's is the rule.

## The dirty guard

On `ui/resource-teardown`, if the form is dirty, it saves before answering.
Chapter 15 explains why that window is the only chance, and Recipe 4 explains
why the flush has to be small enough to finish.

## Live preview without commitment

Changing the accent colour or the density updates the view immediately, and
the change is not saved until Save is pressed. Preview is not commitment, and
a form that saves as you type has no discard.

## Try this

**Clear the email field and click away.** The error appears on blur, not on the
keystroke that made it invalid.

**Type an obviously invalid address and press Save.** Focus moves to the field,
the error is announced, and no tool call is sent.

**Edit something, then press "Close with unsaved changes".** The form saves
inside the teardown window before answering the host.

**Press "Switch to ja-JP / Tokyo".** The stored values do not change and
everything rendered does, which is the whole of Chapter 12 in one button.

## What it needs from the host

| Level | Needs | Without it |
|---|---|---|
| 1 | Render, resize, theme, locale, timezone | Formatting falls back to the machine |
| 2 | `picker.date`, `picker.time`, `picker.color` | Platform; always present |
| 2 | `lifecycle.beforeClose` | Unsaved changes are lost on teardown |
| 4 | `tool.invoke` | Nothing loads and nothing saves |

## What happens when things go wrong

**The server rejects a value the client accepted.** The message is shown, the
form stays dirty, and nothing is marked saved.

**Teardown with unsaved changes.** The view saves inside the teardown window
and then answers.

**A host that sends no locale.** `Intl` falls back to the machine's default,
which is wrong but functional, and the note in the view says which timezone it
is using so the discrepancy is at least visible.

## Keyboard and screen reader

Every field has a real `<label>` with a `for`. Errors are associated through
`aria-describedby` and marked with `aria-invalid`, so a screen reader reads the
error as part of the field. Fieldsets group
related controls with legends. Save failure moves focus to the first invalid
field and announces the reason. The whole form is operable from the keyboard,
which for a form built from native elements means it was operable from the
keyboard before anybody thought about it.

The recipe also registers `focus_field`, which moves focus to a named field
and refuses a name it does not have. That is the workaround for
`surface.focusHandoff` in Appendix B, built rather than described, and it is
worth being exact about what it covers: an agent can move focus, and an
assistive technology driving through an agent can move focus. A host still
cannot, because no message exists, and someone working by keyboard alone gains
nothing from it. The entry in Appendix B stays where it is.

## Conformance checks

1. `load_preferences` populates every field.
2. Editing enables Save and Discard and sets the dirty chip.
3. Blurring an invalid email shows an error; typing an invalid one does not.
4. Save with an invalid email focuses the field and sends no tool call.
5. A server rejection leaves the form dirty and shows the server's text.
6. Discard confirms, then restores the loaded values.
7. Teardown with unsaved changes sends `save_preferences` before responding.
8. Changing the host locale re-renders the formatted values.
