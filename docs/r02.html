Recipe 2

Dashboard

Tiles, sparklines, drill-down, and values that keep changing while you look at them.

At-a-glance monitoring with drill-down.

A dashboard is a data explorer that will not hold still. Its capability delta is entirely about that: values updating in place, a drill-down that does not lose them, and a motion preference that has to be respected by something other than a CSS rule.

What stays local, what crosses

Normally local Worth crossing
Open a tile’s detail panel “What caused the error spike?”
Compare two tiles “Compare this week to last”
Change the time window “Is this normal for a Tuesday?”
Refresh

Refresh is worth noticing. It looks like a crossing and it is not: the view calls the tool directly, and the model is never involved in a button that means “get the current numbers”.

What it looks like

A responsive grid of tiles, minimum 150 pixels each, so the same view is one column in a narrow panel and four across in a wide one. A drill-down panel opens under the grid rather than as a modal, because a modal in a four hundred pixel frame covers everything.

Updating in place

The tile is not rebuilt when its value changes. The text node and the sparkline are replaced; the tile element, its focus and its position stay.

Illustrative, not run

const tile = $("#tiles").firstChild;
tile.querySelector(".v").textContent = `${format.number(m.value)} ${m.unit}`;
tile.querySelector("svg")?.replaceWith(spark(m.series));

Rebuilding the grid on every tick would move focus out of whatever the user was on, twice a second. This is the same discipline Recipe 9 needs at a hundred times the rate.

Sparklines with no dependency

The chart is inline SVG built with createElementNS, eleven lines, stroked with var(--color-text-info) so it follows the host’s theme. The view declares an empty CSP, because it loads nothing. Chapter 23 has the argument for why this is usually the right answer in an embedded frame.

Reduced motion changes the poll, not just the transition

Illustrative, not run

setInterval(() => { /* ... */ }, reduced.matches ? 4000 : 1400);

A stylesheet rule that disables transitions does nothing for a value that repaints continuously. Under a reduced motion preference the dashboard slows down, which is a different response from removing an animation and the correct one for something that is moving rather than animating.

Try this

Watch the first tile for ten seconds. The value and the sparkline change; the tile element does not. Tab to it while it is updating and the focus stays put, which is the entire reason it patches instead of rebuilding.

Open a tile, then press “Show the model context”. The model is told which panel is open, not which tiles were hovered on the way there.

Press “Withdraw fullscreen”, then press Expand. The view checks availableDisplayModes before asking and reports that the mode is gone, instead of sending a request that would be refused.

What it needs from the host

Level Needs Without it
1 Render, resize, theme Nothing works
3 surface.displayMode The expand button is omitted
4 tool.invoke No refresh; the initial result is all there is
4 agent.contextUpdate The model does not learn which panel is open

What happens when things go wrong

Fullscreen withdrawn mid-session. Press “Withdraw fullscreen”. The next press of Expand finds the mode absent from availableDisplayModes and says so rather than sending a request that would be refused.

The refresh fails. The tiles keep their last values and the freshness chip stops advancing, which is the honest signal: a dashboard whose numbers are wrong is worse than one that admits its numbers are old.

Keyboard and screen reader

Each tile is a button with an aria-label that states the metric and its value, so a screen reader user gets “Checkout p95, 412 milliseconds” rather than a heading and a number in separate nodes. Sparklines are aria-hidden="true" and the note under each tile carries the trend in words. Opening a drill-down announces it. The grid is keyboard navigable by tab, and Enter opens.

Conformance checks

  1. Handshake completes and a size is reported.
  2. service_health returns four metrics and four tiles render.
  3. A pushed ui/notifications/tool-result updates values without a call.
  4. Opening a tile sends one ui/update-model-context.
  5. ui/request-display-mode returns the mode the host actually set.
  6. With fullscreen withdrawn, no display mode request is sent.
  7. Under prefers-reduced-motion, the update interval is at least 4 seconds.
