Recipe 6

Image Annotator

A canvas with pointer capture, zoom about the cursor, a dropzone that validates, and an export that degrades to the clipboard.

r06Image AnnotatorNeeds level 3

Label regions on an image.

All capabilities

The spatial recipe. Everything in it is Level 2 and 3 platform behaviour except the export, and the export is where the sandbox shows up.

The split

Normally local Worth crossing
Draw, move and delete boxes “Are these defects the same type?”
Zoom, pan, fit “Label the regions you can see”
Change label and colour “Compare this to yesterday’s plate”
Export

Surface

A fixed-height stage with a transformed world inside it. The image is inline SVG drawn by the view, which is why the recipe declares an empty CSP: a JPEG from a CDN would need resourceDomains and a host willing to allow it.

Zoom about the cursor

Illustrative, not run

const before = scale;
scale = Math.min(6, Math.max(0.4, scale * (event.deltaY < 0 ? 1.12 : 0.89)));
const rect = stage.getBoundingClientRect();
const px = event.clientX - rect.left, py = event.clientY - rect.top;
panX = px - ((px - panX) / before) * scale;
panY = py - ((py - panY) / before) * scale;

Six lines, and they are the difference between a canvas that feels right and one that fights. Zooming about the origin moves whatever the user was looking at off screen, every time.

Pointer capture for the draw gesture

The stage captures the pointer on pointerdown, so a drag that leaves the stage still produces a correctly sized box. Without capture, dragging past the edge stops the gesture and leaves a half-drawn rectangle.

touch-action: none on the stage stops the browser interpreting a drag as a scroll, which otherwise makes drawing impossible on a touch device.

The dropzone that says what it wants

The zone states “Drop a file here” in its resting state and rejects anything that is not JSON with a message naming the file. A dropzone that silently ignores a bad file is indistinguishable from a broken one.

Export, and what happens without it

Illustrative, not run

if (!bridge.hostCapabilities.downloadFile) {
  await navigator.clipboard.writeText(payload).catch(() => {});
  toast("No download capability, so the JSON went to the clipboard");
  return;
}

Press “Refuse downloads” in the demonstration. The button stays, its behaviour changes, and the toast says why. This is the one place in Part V where a missing capability changes what a control does rather than whether it exists, and it is defensible because the underlying user need, getting the annotations out, has an alternative that works.

Host dependencies

Level Needs Without it
1 Render, resize, theme Nothing works

2 file.dropzone Platform; always present
3 input.zoompan Platform; always present
4 tool.invoke No saved annotations to load

Failure cases

A tiny box. Drags under six pixels in either dimension are discarded, so a click on the canvas does not leave an invisible annotation.

A JSON file that is not annotations. Caught by the try around the parse, reported by name, and the existing boxes are untouched.

Accessibility

This is the recipe with the weakest accessibility story in Part V, and saying so is more useful than claiming otherwise. The zoom and pan have button equivalents through Fit. Drawing a box does not: there is no keyboard route to create an annotation, and a complete implementation would need one, most plausibly a form that takes coordinates or a tool the agent can call on the user’s behalf. The existing boxes are announced when loaded, and the label and colour controls are ordinary form fields.

Conformance checks

  1. load_annotations returns two boxes and both render.
  2. A drag creates a box whose dimensions match the drag.
  3. Wheel zoom keeps the point under the cursor stationary within a pixel.
  4. Fit returns the plate to the visible stage.
  5. Undo removes the most recently added box.
  6. With downloadFile present, export sends ui/download-file.
  7. With it absent, export sends no message and reports the clipboard fallback.
