Recipe 7

Workflow Builder

A node graph the agent can edit through tools, with validation that runs continuously and an undo stack that covers both parties.

r07Workflow BuilderNeeds level 4

Build and edit a node graph.

Capability delta

All capabilities

The recipe where the agent is a first-class editor. Everything the mouse can do to this graph, a tool can do, and everything a tool does is one undoable transaction. The topology explorer some applications need is this same surface in read-only mode.

What stays local, what crosses

Normally local Worth crossing
Drag nodes, pan, zoom “Build me a triage workflow”
Connect two selected steps “What is wrong with this graph?”
Add and delete steps “Add error handling to this”
Undo

The second column is the interesting one. All three of those are the agent calling the same operations the mouse calls, which is why they are safe.

The agent’s vocabulary

Four tools: add_step, connect_steps, highlight_step, and get_workflow. Three of them mutate and are annotated readOnlyHint: false; the fourth reads.

Illustrative, not run

bridge.registerTool({
  name: "connect_steps",
  description: "Connect two steps by name",
  inputSchema: { type: "object", properties: { from: { type: "string" },
    to: { type: "string" } }, required: ["from", "to"] },
  annotations: { readOnlyHint: false },
}, async ({ from, to }) => {
  const a = graph.nodes.find((n) => n.name === from);
  const b = graph.nodes.find((n) => n.name === to);
  if (!a || !b) {
    return { isError: true, content: [{ type: "text",
      text: `No step called ${a ? to : from}.` }] };
  }
  connect(a.id, b.id);
  return { content: [{ type: "text", text: `Connected ${from} to ${to}.` }] };
});

Two design decisions in that snippet. The tool takes names rather than internal ids, because names are what appear in the conversation. And it fails with a message naming the step that does not exist, so the agent can correct itself rather than guessing. Press “Agent: connect to a step that is not there” in the demonstration to see the failure path.

Validation as a continuous state

The graph is validated on every change and the result is a chip: valid, or a count of problems. Nodes with problems get a red border. The initial graph loads with a disconnected Notify node, so the recipe starts invalid on purpose.

get_workflow returns the problems as structured data, which is what makes “what is wrong with this graph” answerable without the model reading pixels.

Undo covers both parties

Every mutation goes through the same apply(), whether it came from a pointer or from a tool. The agent adds a step; one Cmd+Z removes it. Chapter 20 argues this is what makes agent editing acceptable, and this recipe is the clearest case: a graph an agent can restructure and a human cannot un-restructure is a graph nobody will let an agent near.

The minimap

Eleven lines of canvas drawing, showing node positions and the current viewport rectangle. It is the cheapest orientation aid available and the first thing users miss on a pannable surface.

Try this

Press “Agent: what is wrong with this?”. The reply is a count of structural problems, computed from the graph rather than described from pixels.

Press “Agent: connect Assign owner to Notify”. An edge appears, the chip goes from “2 problem(s)” to “valid”, and one Cmd/Ctrl+Z removes it.

Press “Agent: connect to a step that is not there”. The tool fails with the missing name in the message, so the agent can correct itself.

Drag a node, then press Undo. One transaction for the whole drag, not sixty.

What happens when things go wrong

The agent names a step that does not exist. The tool returns isError: true with the missing name, and the graph is unchanged.

A node is dragged outside the world. The world is 1200 by 800 and the transform does not clamp, so a node can be dragged out of view. The minimap is how the user finds it again, which is a mitigation rather than a fix.

Keyboard and screen reader

Nodes are focusable and the selection is visible, but this recipe shares Recipe 6’s weakness: there is no keyboard route to draw a connection by position. What it has instead is the tool interface, which a user driving by voice or by assistant can use to do exactly what the mouse does. That is a real answer rather than an excuse, and it is the same mechanism Chapter 18 recommends for accessibility generally.

Conformance checks

  1. load_workflow returns four nodes and two edges.
  2. The validation chip reports two problems on load.
  3. connect_steps with valid names adds an edge and clears one problem.
  4. connect_steps with an invalid name returns isError: true.
  5. Undo removes an agent-created edge.
  6. get_workflow returns the same problem count the chip shows.
  7. Dragging a node produces exactly one undo transaction.
