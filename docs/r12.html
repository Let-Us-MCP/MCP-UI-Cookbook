Recipe 12

Media Viewer

A transport, a caption track, an immersion request that goes through the host, and a share button for a capability that does not exist.

The recipe with the most platform behaviour and the clearest example of a capability the sandbox simply does not have. It is also the recipe that most often should not be built: the native controls are better than the ones here.

What stays local, what crosses

Normally local Worth crossing
Play, pause, seek, captions “What happens at the two minute mark?”
Switch clips “Summarise these three clips”
Go fullscreen “Find the clip where the gripper misses”

Why the controls are custom here, and why yours should not be

The native <video> controls handle keyboard, screen readers, captions, picture in picture, playback rate and every platform convention, in less code than the transport in this recipe. This one is custom because the recipe needs to demonstrate the transport as a component and because it has no media file to ship: the frames are inline SVG, which is also how it avoids declaring any external origin.

If you have real media and no unusual requirement, use the native controls.

Immersion through the host

Element.requestFullscreen() needs the fullscreen permission policy, which is not in the extension’s set of four. The route that works is ui/request-display-mode, and the answer is authoritative:

Illustrative, not run

const target = bridge.hostContext.displayMode === "fullscreen"
  ? "inline" : "fullscreen";
const { mode } = await bridge.requestDisplayMode(target);
$("#note").textContent = mode === target
  ? `Host granted ${mode}.` : `Host refused and kept ${mode}.`;

Press “Offer picture in picture” and then “Withdraw fullscreen” to see the view react to both.

Pausing when hidden

Audio continuing from a frame nobody can see is genuinely alarming, and it is the fastest way to make somebody close a conversation. The player checks document.hidden on every tick and pauses with a note saying why.

A share button with nothing behind it

navigator.share needs the web-share permission policy, which the extension does not have. system.share is a gap. What the recipe does instead is ask the host to open a canonical link, and fall back to putting that link on the clipboard, and say which it did.

That is the general shape for a missing capability with a real user need behind it: find the nearest thing the host will do, do that, and be explicit about the substitution.

Try this

Press Play, then press “Withdraw fullscreen” and the Fullscreen button. The view reports the mode the host actually kept, having assumed nothing about the request.

Press Share with links allowed, then press “Refuse to open links” and press it again. The first goes through ui/open-link; the second falls back to the clipboard and says so. There is no share capability to fall back from.

Turn captions on and scrub. The caption line follows the position, and the toggle carries aria-pressed and no colour change.

What it needs from the host

Level Needs Without it
1 Render, resize, theme Nothing works
1 link.open Share falls back to the clipboard
3 media.playback Platform; always present
3 surface.displayMode The fullscreen button is omitted
3 system.share Gap; link or clipboard is the fallback
4 tool.invoke No clips to list

What happens when things go wrong

Fullscreen refused. The note reports the mode the host kept. The player keeps working at inline size.

Autoplay. The player never attempts it. Everything starts paused, which is both a policy requirement and good manners.

Captions with no track selected. The caption line is hidden.

Keyboard and screen reader

Play carries an aria-label that changes with state. The seek slider has a real name, the captions toggle has aria-pressed, the frame has an aria-label naming the clip, and the thumbnail strip is a tab list with aria-current.

The seek bar carries aria-valuetext in minutes and seconds, so it announces “1:20 of 2:14” and never “80”. A range input announces its raw value otherwise, which is the most common defect in custom transports.

Conformance checks

  1. list_clips returns three clips and the strip renders three thumbnails.
  2. Play advances the clock and Pause stops it.
  3. Hiding the frame pauses playback.
  4. ui/request-display-mode returns the mode the host set.
  5. With fullscreen withdrawn, the button reports the refusal.
  6. Share sends ui/open-link when openLinks is present and does not when it is absent.
