    Recipe 3

    File Explorer

    A tree, a context menu, drag to move, and a deletion that is both confirmed and undoable.

    r03File ExplorerNeeds level 3

    Hierarchical browse and manage.

    Capability delta
    input.contextmenuinput.dragdropinput.longpressdialog.confirmfile.openfile.dropzonesurface.focusnotify.toastpicker.resourceresource.readhistory.undohistory.transaction
    All capabilities
    input.contextmenuinput.dragdropinput.longpressinput.selectionclipboard.writedialog.confirmfile.openfile.dropzonesurface.focusnotify.toastpicker.resourceresource.readhistory.undohistory.transaction

    The recipe that exercises the pointer and keyboard group hardest. Everything in it is Level 2 or below except the tool call that loads the tree, which means it is the recipe most likely to work in a host you have not tested.

    What stays local, what crosses

    Normally local Worth crossing
    Expand and collapse “Summarise what is in this folder”
    Select, rename, duplicate “Find the files that mention the vendor patch”
    Drag to move “Which of these can be archived?”
    Delete, and undo it
    Copy a path

    Every structural operation is local, including the destructive one. That is deliberate: a delete that has to wait for a model is a delete that can fail for reasons the user cannot see.

    What it looks like

    Two panes side by side above 480 pixels, stacked below. A tree on the left, a property list on the right, a toolbar above both. The context menu is absolutely positioned inside the frame and closes on outside click or Escape.

    Confirmation and undo together

    The delete path confirms, and the confirmation says the action can be undone.

    Illustrative, not run

    const yes = await confirmDialog({ title: `Delete ${node.name}?`,
  body: "You can undo this from the toolbar.", confirm: "Delete",
  destructive: true });
if (!yes) return;
apply({ label: `delete ${node.name}`,
        forward: () => parent.children.splice(index, 1),
        back: () => parent.children.splice(index, 0, node) });

    Chapter 9 argues that a confirmation without undo trains people to click through it, and that undo without confirmation loses a folder before anyone notices. Doing both costs four lines and the confirmation stops being ritual.

    Move as a transaction

    Dragging a node onto a folder is one transaction that remembers the index it came from, so undo puts it back where it was. That detail is invisible when it works and obvious when it does not.

    Try this

    Drag notes.txt onto the documents folder, then press Undo. It returns to its original position in its original parent, because the transaction recorded the index and the parent.

    Right click any node. The menu is drawn by the view, positioned inside the frame, and closes on Escape with focus restored.

    Select a file and press Delete. The confirmation says the action can be undone, which is what makes the confirmation honest.

    Tab into the tree, then use the arrow keys. The whole tree is one tab stop.

    What it needs from the host

    Level Needs Without it
    1 Render, resize, theme Nothing works
    2 clipboard.write Copy path falls back to execCommand
    2 input.contextmenu, input.dragdrop Platform; always present
    4 tool.invoke No tree to show

    This recipe needs the least from the host of any in Part V. Its one hard dependency is the tool call that loads the tree, and a host without serverTools can still deliver that through the initial tool result.

    What happens when things go wrong

    The drop target is not a folder. dragover only calls preventDefault() for nodes with children, so the drop never fires on a file and there is no error to report.

    Two menus. A host that shows its own context menu on right click would produce two, and neither party can currently detect the other. Chapter 10 has the gap.

    Keyboard and screen reader

    role="tree" with role="treeitem" children and one roving tabindex, so a hundred-file tree is one tab stop. aria-expanded on folders, aria-selected on the current node. F2 renames, Delete deletes, Cmd/Ctrl+Z undoes. The context menu is reachable from the keyboard and moves focus to its first item. Every action announces its outcome, including undo.

    Conformance checks

    1. Handshake and size report.
    2. list_files returns a tree and it renders with three top-level entries.
    3. Arrow keys move selection without changing the tab stop count.
    4. Delete opens a dialog; Escape cancels it and nothing is removed.
    5. Confirming removes the node and enables Undo.
    6. Undo restores the node at its original index.
    7. Dragging a file onto a folder moves it; dragging onto a file does nothing.
